# 使用先を変えてもキャラクターの印象を保つ

[工程索引](process-index.md) · [材質と画像の対応](adjustment-methods.md#uv画像材質を一組で渡す) · [シェーダーの取得と対応範囲](shader-setup.md)

銀・宝石・冠・金具の補正対象を決める時は[アクセサリーの材質判断と具体手順](accessory-materials.md)へ。立体の欠け・誤接続を見つけたら[メッシュ修復](mesh-repair-completion.md)で形を確認してから外観を合わせます。

同じモデルと画像でも、色の読み方、光、影、輪郭線、透過の方式が違うと印象が変わります。**全体の表示設定、特定の素材、描画仕様の差を分けてから直します。** 別のエンジンへ渡す時と、映画などでショット間の見た目を揃える時に使います。

## 開始時に決めること

| 項目 | 短く記録する内容 |
| --- | --- |
| ゴール | 用途と距離に合う顔・髪・目の色、陰影、輪郭を保つ。画素の一致が必要なら対象と許容差も別に決める |
| 入力 | 基準モデル・画像・材質プリセットの版、使用先とシェーダーの版 |
| 変更と固定 | 今回直す表示設定または材質。形・UV・骨・表情など保持する項目 |
| 比較 | 同じカメラ位置・画角・解像度・姿勢・主光・固定露出。顔の正面・斜め・横と全身 |
| 終了と提出 | 保存後の使用先でも基準の印象を保ち、前後画像・変更値・保持結果・仕様差と残件を渡せる |

## 調整する順番

1. **比較条件を揃える。** 上表のカメラと光を記録し、露出を固定する。比較の妨げになるブルームやショット固有の色補正はいったん外す。本番の演出を禁止する意味ではありません。
2. **画像と色管理を確認する。** 通常のsRGB基本色画像はsRGB、数値マスクはlinearとして読むなど、画像の役割と元の色空間に合わせる。法線画像の誤判定・圧縮、露出、トーンマッピングも確認する。設定が誤ったまま、画像を塗り直して帳尻を合わせない。
3. **基本色と影を切り分ける。** 全体が違えば表示設定、口など一部だけ暗ければその材質を単独確認する。診断用コピーで基本色・AO・影・法線・艶を一つずつ外し、実際に見えている面と画像を特定する。
4. **陰影と髪の艶を合わせる。** 影の境界・濃さ、髪の落ち影、MatCapの強さと位置を別に調整する。MatCapは見る方向で変わる艶の表現なので、正面だけで合格にしない。使用先にない落ち影は、係数を揃えれば復元できるとは扱わない。
5. **輪郭と透過を確認する。** 顔アップと全身で線幅を見て、羽や髪は明るい背景・暗い背景、重なりのある向きと動作で確認する。切抜きと半透明では縁や描画順が違うため、用途に合う方式を選ぶ。
6. **保存して読み直す。** 修正した材質と画像を実ファイルへ保存し、使用先で再読込する。複数角度と必要な表情・動作を比較し、旧プリセットや再生成処理で修正が戻らないことも確認する。

一つの変更で良くなった後は、対象外も同条件で確認します。小さい差は撮影順や描画の安定待ちによる揺れも調べ、原因未確認のまま素材を重ねて直しません。

## 口の中だけ黒く見える時

口の中には、口袋・舌・歯・唇の内側があります。どの面が暗く見えているかを、材質ごとの色分け表示などで先に特定します。顔全体の光を強める前に、**その面の基本色だけを、光・AO・影から切り離して確認**してください。動画だけで暗い場合は、同じフレームの保存画像と動画・仕上げ後を並べ、書き出しや色変換の黒つぶれと素材の問題を区別します。

- 取り込み・露出・色管理が正常で、基本色だけの描画も暗い場合は、元の色を確認します。明るさの異なる少数案を比較し、歯・舌との区別、開口「あ」「お」、閉口・笑顔を確認します。特定の色を全キャラの既定値にしません。
- 基本色だけなら自然な場合は、AO、影、落ち影、面の重なりなどへ戻って診断します。口の暗さを理由に、全身の影を一括で消しません。
- 共通の色が原因なら、基準素材と各出力用プリセットへ対応して反映します。基本色に掛ける影の色味と、独立した影色を持つ材質では、更新する値が異なります。

リダの制作では口袋の基本色が暗く、影や光を変える効果は小さかったため、基本色だけを変更しました。Blender・VRMの確認に加え、Unity・UEでも同じ方向の改善を実描画で確認しています。**共通素材の修正であり、エンジン固有の差を解決した例ではありません。**

AIへの指示例：

> 口の黒さが出る表情と、同条件の通常顔を確認してください。まず見えている面を特定し、口袋の基本色を光・AO・影から切り離して原因を示してください。必要なら口袋の色だけ少数案で比較し、形・表情・他材質は保持。開口の正面と斜め、閉口・笑顔を保存後の使用先でも確認し、変更値と対象外の保持、残件を報告してください。

## 羽の縁に暗い線が出る時

透過画像の縁は、**基本色だけでなく、影色の画像とアルファも一緒に調べます。** 基本色だけを直すと、影になった側で暗い縁が残る場合があります。

1. 同じ羽を明暗両背景で拡大し、基本色・影色・アルファを分けて表示する。透過の描画順、切抜き閾値、輪郭線が原因の線と区別する。
2. RGBへアルファを掛けた画像か、掛けていない画像かを確認し、シェーダーが期待する方式と揃える。既に正しい画像へ割り戻しを重ねない。
3. 画像側の補正が必要な場合だけ、別出力へ作る。影色がRGB画像なら、対応する基本色画像などの正しいアルファを参照する。アルファ0付近を単純に割らず、見える羽の色を透明側へ広げる方法も使う。
4. 画像寸法、元のアルファ、不透明部分、対象外画像を保持し、基本色と影色の両方を使用先へ渡す。保存後に明暗両背景・羽全体・重なり動作で再確認する。

リダのVRMでは基本色だけの修正では足りず、影色画像にも暗い縁が残っていました。対応するアルファを使って両方を直し、アルファ自体は保持しました。確認したのはVRMの読み戻し描画で、全アプリの半透明順序が解決したという意味ではありません。

AIへの指示例：

> 羽の暗い縁を、基本色・影色・アルファ・輪郭線・透過方式に分けて診断してください。画像補正が必要なら、RGBとアルファの方式を確認したうえで両方の色画像を別出力へ直し、元のアルファと不透明部分を保持してください。明暗両背景の拡大、羽全体、重なり動作を使用先で比較し、保存画像の版と未検証範囲を記録してください。

## ショット間で同じキャラクターに見せる

次は制作比較から整理した運用案で、映画全編で実証した工程ではありません。

- **キャラクターの基準を保存する。** 固定した比較用の光で、顔の正面・斜め・横と全身を撮る。材質プリセット、基本色・影・艶・輪郭の特徴と使用版を一緒に保存する。
- **ショットの演出を別に記録する。** 本番の照明・露出・カラー調整はショット側に残す。色が変わった時は撮影条件を先に確認し、毎回キャラクターの素材色を塗り替えない。
- **仕上げ後にも並べる。** 本番の色補正・解像度・圧縮後の顔とシルエットを基準と比較する。必要な意図的変更は記録し、次のショットへ偶然の補正を持ち越さない。

AIへの初回指示例：

> 添付の基準モデルと材質プリセットを使い、記録したカメラ・光・固定露出で顔の正面・斜め・横と全身を比較してください。画像の取り込みと色管理を確認してから、基本色、影、髪の艶、輪郭、透過を別々に調整してください。形・UV・骨・表情は保持。提出は同条件の前後画像、変更値、使用先での保存読込結果、仕様差と残件です。最後に本番ショットの色補正後も基準と並べ、キャラクター材質の変更とショット側の変更を分けて記録してください。

## AngelToonで確認する範囲

調整工数の順位や、初期値だけで3環境が同じ外観になる保証はありません。公開比較のBlender列は制作時の基準材質で、配布Blenderアドオンの実モデル適用例とは区別します。Unity・UEにもモデル専用の画像・マスク・プリセットを設定しています。

現在のUE実装はUnlit方式で落ち影を受けないため、髪の奥行きの見え方などに差が残ります。VRMのMToonは別の材質仕様です。導入・版・対応環境は[シェーダーの取得](shader-setup.md)、比較条件は次の資料を確認してください。
