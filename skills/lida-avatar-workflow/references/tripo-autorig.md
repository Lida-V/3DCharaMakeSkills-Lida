# FBXをTripoでオートリグしてから調整する

[日本語](tripo-autorig.md) · [English](en/tripo-autorig.md)

新規の動く人型モデルでは、**通常形と曲がる部分の網目を整える → FBXをアップロード → TripoでVRM 1.0の骨格を選んでオートリグ → 骨・ウェイトを調整**する工程を入れます。最初から全身の骨を手作業で作る計画へ直行しないでください。使えるリグが既にある修正依頼や、動かさない用途では再オートリグを必須にしません。

[制作計画](production-plan.md) · [工程索引](process-index.md) · [骨・網目・重みの調整](mesh-weight.md)

## 開始時のゴールと入力

この工程のゴールは、採用した形を保ち、VRM 1.0用の人型骨格と初期ウェイトを受け取り、リグ調整へ渡せる状態です。完成VRMの提出とは分けます。

- 採用した通常形、正面・横の基準画像、単位・左右前後・基準姿勢。
- 保護原本とは別のアップロード用FBX。対象メッシュ、含める部品、除外部品と復元先を記録。
- ファイルの実容量、既存のUV・材質画像・表情キー・骨の有無。往復で保持するものを明示。
- 必要な動作、使用先、受領した骨格・ウェイトの確認項目と後工程の残件。

肩・股・指が判別できる姿勢を使い、重なりや融合、大きい欠けを先に直します。指や関節の網目は[変形を考えた構造](mesh-weight.md)で準備し、オートリグ後も実際の曲がり方で再評価します。

## アップロードはFBX、上限は150MB

**送信するFBXそのものを150MB以内にします。** ZIPの圧縮後サイズや元の制作ファイルの容量では判定しません。[FBX条件確認CLI](model-tools.md#tripoへ送るfbxの容量と識別形式を調べる)で実容量・識別形式を調べられます。ヘッダの適合は完全な構文やTripo受付成功の保証ではありません。実バイト数と画面の上限表示を記録し、上限ぎりぎりを避けてください。ユーザー指定の150Mは、[Tripoのアップロード画面](https://studio.tripo3d.ai/ja/workspace/rigging?open=login)の「≤150MB」とも一致します（2026-10-19確認）。利用時の表示が変わった場合は、その条件を確認します。

容量を超える場合は、**コピーだけ**で次の順に調べます。

1. 撮影用の背景・小物、重複オブジェクト、不要な動作データなどを出力対象から外す。必要な身体・関節や保持対象まで一緒に除外しない。
2. 埋め込み画像が大きければ、リグ入力用だけ画像を縮小・省略し、元のUV・画像・材質を保管する。取り込み後に元へ戻して比較する。
3. それでも必要なら、対象部品の分離や軽い代理メッシュを検討する。代理を使う場合は元モデルへの骨・ウェイトの対応付けと動作検証まで計画し、軽量版で完成原本を置き換えない。

容量だけを理由に顔・指・関節を一律に粗くしません。アップロードに使ったFBXの名前・版・実容量、除外や軽量化の内容を残します。

## オートリグから調整へ進む手順

1. **FBXを確認する。** 出力したFBXを読み戻し、縮尺・向き・通常形と対象部品を照合する。旧リグや動作を外す必要がある場合もアップロード用コピーに限定し、外したものを記録する。
2. **Tripoへアップロードする。** オートリグの人型用設定で、骨格プリセットを明示的に「VRM 1.0」へ合わせる。標準設定のまま別の骨格で進めない。実行前の互換性チェックが使える場合は結果を確認する。
3. **結果を別名で受け取る。** 使用した設定・入力FBXと受領ファイルを対応させ、利用可能な出力形式で保存する。アップロード形式FBXと、受領時の形式は分けて記録する。
4. **原本との違いを調べる。** 同条件の通常形、頂点・面の対応、UV、材質と画像、既存キーを比較する。往復で対応が変わった場合は、旧頂点番号のままキーやウェイトを移さない。良い原メッシュへ新骨格と重みを対応させるなど、保持できる経路を選び、変換差を確認してから次へ進む。
5. **骨を先に、次に網目とウェイトを調整する。** [骨構成のCLI](model-tools.md#骨構成と人型への割当を調べる)で明示したリグと対応表を調べ、[画像・動作の判定](mechanical-visual-review.md)も分けて記録する。 本人左右、親子関係、人型への割当、関節中心、局所軸、基準姿勢を調べる。曲がる位置が違えば骨を直し、面の流れと重みの遷移を合わせる。[骨と基準姿勢の確認](mesh-weight.md#網目を直す前に骨と基準姿勢を確かめる)と[手指の骨・重み](hand-shape.md)を使う。名前が合うだけで割当成功としない。
6. **動作と保存を確認する。** 肩・肘・股・膝・足首・手指について用途に必要な単独・左右・複合動作の途中、最大、戻りを確認する。服・髪・装飾の追従と貫通も照合し、別名保存・再読込する。変更部と保持部、必要な表情・揺れ・使用先の残件を次へ渡す。

オートリグは調整の出発点です。人型に翼がある場合も、身体の人型骨格と翼の補助骨は分けて設計します。髪・翼・衣装の支持、眼球の視線、表情キー、揺れが自動で完成するとは扱いません。網目を大きく作り直した場合は重みと依存部品を再対応し、オートリグだけを無条件に繰り返さず原因を診断します。

## つまずいた時の判断

| 症状 | 先に確認すること | 調整の方向 |
| --- | --- | --- |
| 容量超過 | 実際の送信FBX、埋め込み画像、出力対象 | コピーの不要データから整理し、必要な形は保持 |
| 骨が違う・人型割当が不明 | 選んだプリセット、実際の骨・階層・左右 | VRM 1.0の対応を確認し、名前変更だけで済ませない |
| 曲がる場所がずれる | 関節中心・軸・基準姿勢 | 骨を修正してから網目とウェイトを調整 |
| 形や表情が変わる・消える | 受領メッシュと原本の対応、既存キー | 受領結果で原本を上書きせず、保持できる経路へ戻す |
| 身体は動くが服や飾りが外れる | 同じ骨への対応、ウェイト、親子・変形の二重適用 | 依存部品を同じ版へそろえ、動作と貫通を再確認 |

## AIへ渡す短い指示

> 動く人型モデルの制作計画に、通常形と関節の網目の確認後、Tripoでのオートリグを一度入れてください。原本を残し、150MB以内のアップロード用FBXを作り、VRM 1.0骨格を選んでください。受領した骨格と初期ウェイトは、形・UV・材質・既存キーの保持を照合してから、関節中心・軸・基準姿勢・人型割当、網目と重み、服や装飾の追従を調整してください。容量対策はコピーで行い、通常・途中・最大・戻り、保存と使用先の確認範囲、後工程の残件を記録してください。使えるリグが既にある箇所は再生成不要です。

## 仕様と確認範囲

[Tripo公式Auto Rig仕様](https://developers.tripo3d.ai/en/docs/animations-rig)にはFBX入力・150MB上限・人型のVRM 1.0骨名規約が記載されています。これは**骨格規約**であり、表情・材質・視線・揺れ・メタ情報を含む完成VRMファイルの保証ではありません。[VRM 1.0人型仕様](https://github.com/vrm-c/vrm-specification/blob/master/specification/VRMC_vrm-1.0/humanoid.md)との割当と、[実出力の読み戻し](visual-handoff.md#vrmを読み戻し提出動作を確認する)を別に確認します。

この章はユーザーが確認した制作経路を今後の手順へ組み込んだものです。過去の全モデルをこの方式で制作した、今回FBXの送信やオートリグ実行まで完了した、という記録にはしません。
