# 見落としやすい所をスクリプトで確かめる

[日本語](automated-checks.md) · [English](en/automated-checks.md)

[工程索引](process-index.md) · [同梱ツール](model-tools.md) · [機械検査と見た目の検品](mechanical-visual-review.md)

**書き出しが「成功」と出たのに設定が抜けていた、曲げたら飾りが割れた、途中の値だけ表情が崩れた、古い版の動画を新しい版として見た、消したフォルダを残したファイルが読んでいた。** どれも、目と記憶で確かめていて実際に見落とした所です。ここでは、その 5 つを決まった手順で確かめる同梱ツールをまとめます。

どのツールも測定と一覧だけを行います。入力は読むだけで、保存・削除・移動はしません。報告は新しい場所へだけ書きます。数値が通っても、見た目と使用先の動きは別に確かめます。

| 確かめること | ツール | 動かす場所 | いつ使うか |
| --- | --- | --- | --- |
| [1 書き出した VRM の設定](#1-書き出した-vrm-の設定) | `lida_vrm_check.py` | 通常の Python | VRM を書き出すたび。アプリへ入れる前 |
| [2 固い飾りが 1 つの塊で動くか](#2-固い飾りが-1-つの塊で動くか) | `lida_rigid_group_check.py` | Blender | ウェイトを付けた・付け直した後 |
| [3 表情キーの途中と組み合わせ](#3-表情キーの途中と組み合わせ) | `lida_shape_key_sweep.py` | Blender | キーを作った・直した後。出力の前 |
| [4 確認画像と保存版の対応](#4-確認画像と保存版の対応) | `lida_evidence_manifest.py` | 通常の Python | 確認用の画像・動画を作った時と、見せる前 |
| [5 整理・移動の前の参照](#5-整理移動の前の参照) | `lida_reference_check.py` | Blender と通常の Python | 途中ファイルを消す・フォルダを動かす前 |

形の当たりは別の章です：[飾りを体・頭へ合わせる](accessory-fit.md)、[貫通を数値で見つけて、直し方を決める](penetration-check.md)。版どうしの比較・ウェイトの総和・骨と人型の対応は[同梱ツール](model-tools.md)にあります。

## 共通の約束

- 入力は保存済みのファイルを指定する。Blender を使うものは、別の背景プロセスで開き、保存しない。
- 報告の JSON は新しいパスへだけ書く。既にあると止まる。
- 終了コード：0＝見つからなかった、2＝見つかった・警告がある、1＝入力や実行の誤り。
- 引数の不足など使い方の誤りも 2 で止まり、JSON は作られない。今回作られた JSON の `status` で区別する。
- 報告の `unverified` に、そのツールが確かめていない範囲が入っている。完了の報告へ写す。
- AI は、結果を読んで原因を調べ、直すかどうかをユーザーの指定と照らす。ツールの 0 を完成の根拠にしない。

## 1 書き出した VRM の設定

書き出しは成功と出ても、ファイルの中の設定が抜けていることがあります。`lida_vrm_check.py` は VRM（glb）の中の JSON と画像の先頭だけを読み、次を確かめます。Blender も numpy も要りません。

| 見る所 | 警告になる例 |
| --- | --- |
| 材質 | MToon にならず PBR のまま出た材質がある。半透明なのに深さを書く材質がある（羽や髪の板で、透明な所が奥を隠す） |
| 揺れもの | 重力の向きが下（VRM の Y 上の軸で 0, −1, 0）でない。当たり判定を使う鎖なのに、関節の当たり半径が全部 0。当たり判定のグループが空・参照先が無い・どの鎖にも使われていない |
| 人型 | 必須の 15 本が欠けている。同じノードを 2 つの骨が指している |
| 視線 | 原点が頭の骨の後ろや下にある（軸の取り違え） |
| 表情 | 既定の表情（母音 5・瞬き 3・感情 5）が無い。モーフの番号がメッシュのモーフ数を超えている。中身の無い表情 |
| メッシュ | UV の無い部品。ウェイトと骨の片方だけ |
| 画像 | 上限（既定 2048）を超える。PNG・JPEG 以外 |
| 拡張 | 読み込み側が対応しないかもしれない必須の拡張 |

```sh
python lida_vrm_check.py check --input model.vrm --report vrm_check.json
```

- `--max-texture 4096`・`--expect-mtoon any|ignore`・`--expect-expressions aa ih …`・`--allow-extension 名前` で、その制作の決まりに合わせる。
- 報告の `springs`・`materials`・`meshes`・`images` に数が出る。前の版の報告と数を並べると、意図しない増減が分かる。
- VRM 0.x は、材質・重力・当たり半径・画像だけを見る。
- 視線を骨で動かす設定では、lookUp などの表情が空なのは普通なので警告にしない。
- 視線の原点は頭の骨の向きで書かれている。頭の骨と親の回転を掛けてモデルの向きへ直してから、後ろ・下にあるかを判定する（報告の `look_at.offset_in_model_space`）。骨の回転を残す書き出しでは、ファイルの中の値の z が負でも正常なことがある。

確かめていないこと：使用先での見え方と揺れ方、形・ウェイト・モーフの中身、当たり判定の大きさが体に合っているか。

## 2 固い飾りが 1 つの塊で動くか

宝石と台、星と石のように、一緒に動くはずの部品が別々のウェイトを持つと、関節を曲げた時に離れます。`lida_rigid_group_check.py` は、組にした部品のウェイトを読み、ウェイトのある骨を 1 本ずつ ±30° 回して、組の全体に「いちばん合う剛体の動き」を当てはめ、そこから外れる量を mm で出します。

```sh
blender --background --factory-startup --disable-autoexec --python-exit-code 1 --python lida_rigid_group_check.py -- check --input model.blend --rig Armature --group Gem Setting --group Tiara --group Bodice@GemMaterial --report rigid.json
```

- `--group` を繰り返して、組を 1 つずつ指定する。`物体@材質` と書くと、その材質の面だけを組にできる（まとめた物体の中の宝石など）。
- 報告の `weight_rows` は、組の中にあるウェイトの組み合わせの数。`largest_deviation_mm` が外れる量、`worst_pose` がその時の骨と軸。
- 読み方：

| 状態 | 意味 | 行うこと |
| --- | --- | --- |
| 骨 1 本・ウェイト 1 通り | 完全に固い | そのまま |
| 骨 2 本以上・ウェイト 1 通り | 離れないが、骨どうしが開くと少しゆがむ | 外れる量が小さければ可。下の面への沈みと浮きを別に見る |
| ウェイトが何通りもある | 部品や頂点が別々の骨に付いていて、曲げると割れる | 組の全頂点を同じ値にそろえる。報告の `mean_row`（平均）が出発点 |

- 鎖・つなぎの輪のように、わざと曲がる部品は組に入れない。入れると割れとして出る。
- 既定の許容は 0.3mm、角度は 30°（`--tolerance-mm`・`--angle`）。

確かめていないこと：実際のポーズと動き、体積を保つスキニング、下の面への沈みや浮き。計算は線形のスキニングで行い、シーンにポーズは付けません。

## 3 表情キーの途中と組み合わせ

0 と 1 では正しく見えるキーが 0.35 で折れる、単独では良い 2 つのキーが混ぜると崩れる、ということが起きます。`lida_shape_key_sweep.py` は、キーと組み合わせを細かい刻み（既定 20）で動かし、いちばん悪い値と、その時の値を出します。

| 測るもの | 意味 |
| --- | --- |
| `folds` | 隣の面へ折り返した面の数（休みで 120° 未満だった面どうしが 150° を超えた） |
| `collapsed` | 面積が休みの 5% 未満に潰れた面の数 |
| `stretch` | 辺がいちばん伸びた倍率（休みで 1mm 未満の辺は除く） |
| `new_crossing_spots` | 相手（眼球・歯）と交わる箇所が、休みより増えた数 |

まぶたの縁は、休みでも眼球に 1 つの輪で触れています。そこで、交わる線の長さではなく、離れた箇所の数を数えます。途中で眼球がまぶたを突き抜けると、箇所が 1 つ増えます。

```sh
blender --background --factory-startup --disable-autoexec --python-exit-code 1 --python lida_shape_key_sweep.py -- sweep --input model.blend --object Face --all --combo happy+blink happy=1+blink aa+happy --partners Eye_L Eye_R Teeth --report sweep.json
```

- 組み合わせは `a+b`（両方を 0→1）と `a=1+b`（a を 1 に固定して b を動かす）。出力先の規則（VRM の override など）で実際に起きる組み合わせを書く。
- **承認済みの版を基準にする**：閉じた目のまぶたの重なりのように、意図した折り返しも数に出ます。見た目を了承した版の報告を `--accept` に渡すと、その値より悪くなった所だけが問題になります。最初の 1 回は全部の項目を画像で確かめ、了承した報告を基準として残します。
- 相手の物体が同じ名前のキーを持つ時は、同じ値で一緒に動かす（歯や影の層）。
- 報告の `driven_keys` は、ドライバーで動くキーの一覧。
- 何も動かさないキーは `the key moves nothing` として問題に出る。`--accept` を渡しても残る。意図して空にしたキーは、報告を読んで判断する。
- しきい値はオプションで変えられる：`--steps`（刻み、既定 20）、`--fold-from-degrees`／`--fold-degrees`（120／150）、`--collapse-ratio`（0.05）、`--stretch-limit`（3.0）、`--min-edge-mm`（1.0）、`--moved-mm`（0.01）、`--spot-mm`（3.0）、`--fold-limit`・`--collapse-limit`・`--spot-limit`（各 0）。`--keys` で調べるキーを絞れる。作例の値で、品質の基準ではない。

確かめていないこと：表情の見た目、閉じた目のすき間、ドライバーやスライダーの上限、キーの後のモディファイア（細分割）と法線。このツールはファイルのキーの値を変えません。

## 4 確認画像と保存版の対応

モデルを同じ名前で保存し直した後に、古い動画を新しい版の確認として見てしまうことがあります。`lida_evidence_manifest.py` は、確認用の画像・動画と、その元になった保存版の大きさと SHA-256 を 1 つの記録にまとめ、後から照合します。

```sh
python lida_evidence_manifest.py record --sources model.blend model.vrm --media sheet.jpg turn.mp4 --manifest evidence.json --note "正面と表情の確認"

python lida_evidence_manifest.py verify --manifest evidence.json
```

| 照合の結果 | 意味 | 行うこと |
| --- | --- | --- |
| `same` | 記録した時と同じ | そのまま使える |
| `stale` | 画像は同じだが、元のモデルが変わった | 今の版から作り直すか、旧版の資料と明記する |
| `changed` | 画像・動画が差し替わった | 記録を取り直す |
| `missing` | ファイルが無い | 場所を確かめる |

- 画像・動画を作ったら、その場で `record` する。ユーザーへ見せる前と、採用の記録を書く前に `verify` する。
- パスは記録からの相対で保存する。フォルダごと動かしても照合でき、ローカルの絶対パスは記録に入らない。
- 記録と対象は同じドライブに置く。

確かめていないこと：その画像が見るべき所を写しているか。照合が合うのは「どのファイルを見たか」だけです。

## 5 整理・移動の前の参照

途中ファイルを消す・フォルダを動かすと、残した Blend の画像が抜けたり、残したスクリプトが動かなくなったりします。`lida_reference_check.py` は、消す前に「まだ何が頼っているか」を挙げます。

```sh
blender --background --factory-startup --disable-autoexec --python-exit-code 1 --python lida_reference_check.py -- blend-refs --inputs keep_a.blend keep_b.blend --report refs.json

python lida_reference_check.py impact --targets stage/work stage/raw --refs refs.json --scan stage/scripts notes --report impact.json
```

1. `blend-refs`：残す Blend を 1 つずつ読むだけで開き、外のファイル（画像・ライブラリ・音・フォント・キャッシュ・動画）の場所、あるか、Blend の中に入っているかを一覧にする。もう見つからないファイルもここで分かる。
2. `impact`：消す・動かす対象（`--targets`）に対して、
   - 残す Blend の外部ファイルのうち、対象の中にあるもの（`would_break`）
   - 残すスクリプト・メモ・設定のうち、対象のパス、または最後の 2 階層を書いている行（`path_mentions`）
   - 対象の中のファイル名だけを書いている行（`name_mentions`、弱い手がかり）
   を挙げる。
- `would_break` と `path_mentions` が 0 になってから消す。`name_mentions` は行を読んで判断する。
- Blend を別の場所へ動かす時は、先に相対パスの外部ファイルを `blend-refs` で確かめる。移した後に開いて保存すると、切れたパスのまま書き換わる。
- 報告にはローカルのパスが入る。作業用の記録で、公開する資料には入れない。
- このツールは何も消さず、動かさない。消す作業は、ユーザーの承認を得てから別に行う。

確かめていないこと：指定しなかった Blend・フォルダ・ほかのプロジェクト、実行時に変数で組み立てるパス、Blender 以外のアプリが読むファイル。

## AI への依頼文の例

```text
<版> を書き出した VRM を lida_vrm_check.py で点検し、警告を 1 つずつ原因と一緒に報告してください。
前の版の報告 <場所> と、材質・揺れもの・メッシュ・画像の数を並べてください。入力は変えないでください。
```

```text
<版> の顔 <物体> のキーを lida_shape_key_sweep.py で全部調べてください。相手は眼球と歯です。
組み合わせは <使用先の規則で起きる組> を入れ、承認済みの報告 <場所> を --accept にしてください。
悪くなった項目は、その値の画像を付けて報告し、直す前に私へ確認してください。
```

```text
<フォルダ> を消す前に、残す Blend <一覧> と、残すスクリプトのフォルダ <一覧> を lida_reference_check.py で調べてください。
would_break と path_mentions が 0 でない間は消さず、該当の行を報告してください。削除は私の承認の後に行ってください。
```

## 確認済みの範囲

- `lida_vrm_check.py`：実際に書き出した VRM 1.0 の 3 ファイル（約 52〜217MB）を読み、揺れもの 48 鎖・関節 169・当たり判定 25・グループ 11、MToon 77、画像 205 枚・最大 2048 が、制作時の記録と一致した。半透明で深さを書く羽の材質 14 が残っていた版では、その警告が出た。
- `lida_rigid_group_check.py`：Blender 5.3.0 の背景実行で、骨 109 本のモデルの 5 組を読むだけで調べた。頭の飾りは外れ 0mm、わざと曲がる金具を含む首飾りは 11.7mm、足首の飾りを含む部品は 5.7mm と出て、制作時のウェイトの記録と合った。
- `lida_shape_key_sweep.py`：同じモデルの顔（キー 14、5,917 頂点）と眼球・歯で、単独 14 と組み合わせ 4 を約 9 秒で調べた。同じ報告を `--accept` に渡すと問題 0 になることを確かめた。
- `lida_evidence_manifest.py`・`lida_reference_check.py`：自作の小さな Blend と画像で、記録・照合・外部画像の検出・スクリプトの行の検出を実行した。
- 5 つとも、通常 Python の回帰テストがある（[テストの説明](model-tools.md#確認済みの範囲)）。

未確認：ほかの Blender 版、VRM 0.x の実ファイル、UniVRM や各ビューアでの読み込み結果との突き合わせ、表情の検査で見つかった項目を直した結果、実際の整理作業での運用。作例の数を品質の基準にしません。
